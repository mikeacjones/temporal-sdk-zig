In a project that depends on the SDK, `testing.TestServer` and `WorkflowEnvironment.startTimeSkipping` now download the newest time-skipping test server release the SDK's own tests pass with, v1.41.1, by default; before, they downloaded the release sdk-core picks, usually the newest, which hangs tests that send an update when that release is v1.41.0. To get sdk-core's choice back, pass `.@"test-server-version" = "default"` in the SDK's `b.dependency` arguments (spelled as the build option is: Zig only logs an argument the SDK doesn't declare, such as `.test_server_version`, and builds on without it). See [Testing](https://github.com/mikeacjones/temporal-sdk-zig#testing).
