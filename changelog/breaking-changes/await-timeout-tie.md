`workflow.Context.awaitTimeout` returns true when its timer fires in the same workflow task as the change that makes its condition true, such as a signal or activity result that arrived while the worker was down, including a change another coroutine makes in that task; it returned false before, although the condition held. When it does return false, it now resumes after the task's other coroutines have run instead of in the order the timer was delivered. A history recorded in either situation may now fail with a nondeterminism error: guard the code after the call with `workflow.Context.patched`, or replay that history with the previous release.
