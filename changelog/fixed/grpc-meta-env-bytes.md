`client.loadOptions` no longer aborts the process when the environment holds a variable that isn't valid UTF-8. A `TEMPORAL_GRPC_META_<NAME>` value is kept as bytes and checked with the other `Options.headers` when the client is created, so a binary header can carry any bytes and an ASCII header with a non-ASCII value fails with `error.InvalidOptions` naming it. Another `TEMPORAL_` variable that isn't UTF-8 returns `error.InvalidConfig`, logged with the variable's name, when the configuration reads it; one it doesn't read is ignored.
