`WorkflowRun.get`, `getWithOptions` and `WorkflowEnvironment.getResult` keep waiting on a run that is still open when the run's description holds a payload the client's codecs can't decode, such as heartbeat details written by a worker with another codec; they used to fail with `error.CodecFailed`. The status check after an empty history page no longer runs the codecs over the DescribeWorkflowExecution response. `Client.describeWorkflow` still decodes its response through the codecs.
