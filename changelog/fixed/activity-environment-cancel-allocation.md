Under `testing.ActivityEnvironment` in a Debug build on macOS, a cancel (`ActivityEnvironment.cancel`, or canceling the calling task) is no longer lost, and the activity no longer hangs, when the activity allocates through `activity.Context.allocator` while std's stack capture waits for the debug info. The environment now blocks cancels around each of the activity's allocations, as a worker does, so the cancel reaches the activity's next wait.
