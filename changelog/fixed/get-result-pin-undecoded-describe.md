`testing.WorkflowEnvironment.getResult` and its variants, given a handle with an empty run ID, now pin the latest run through the new `client.Client.latestRunId`, which reads the run ID without decoding the run's description, so a payload the client's codecs can't decode that only the description holds, such as a pending activity's heartbeat details, no longer fails them with `error.CodecFailed`; `Client.describeWorkflow` still fails on such a payload.
