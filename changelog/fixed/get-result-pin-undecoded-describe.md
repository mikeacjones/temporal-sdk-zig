`testing.WorkflowEnvironment.getResult` and its variants no longer fail with `error.CodecFailed` on a handle with an empty run ID when the run's description holds a payload the client's codecs can't decode, such as a pending activity's heartbeat details or a memo; the run is now pinned through the new `client.Client.latestRunId`, which reads the latest run ID without decoding the description, while `Client.describeWorkflow` still fails on such a payload.
