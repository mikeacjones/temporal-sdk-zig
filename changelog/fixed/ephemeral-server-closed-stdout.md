`bridge.EphemeralServer.startDevServer` and `startTestServer`, and so `testing.DevServer.start` and `testing.TestServer.start`, no longer close this process's stdout or stderr while the server starts when that fd was already closed and the output is `.discard`: the server ran without output there and the next file any thread opened received stdout or stderr writes. Such an fd now has /dev/null on it while the server starts and is closed again afterwards, rather than left open on /dev/null.
