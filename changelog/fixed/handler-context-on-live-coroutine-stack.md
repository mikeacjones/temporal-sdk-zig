`workflow.Context.setQueryHandler`, `setSignalHandler`, `setUpdateHandler` and their dynamic and `ByName`/`WithOptions`/`WithValidator` forms now reject a context that points into the stack of any live workflow coroutine of the run, not only the calling coroutine's, with the same `error.QueryContextOnStack`, `error.SignalContextOnStack` or `error.UpdateContextOnStack`. Before, a handler coroutine (or one started with `io.async`) could register with a pointer to a local of the workflow function, and the handler then read a reused stack once that function returned.
