Workers answer the `__enhanced_stack_trace` query (`workflow.EnhancedStackTraceQuery`) for every workflow, with each coroutine's call sites in workflow code and excerpts of the source around them, and the `__temporal_workflow_metadata` query (`workflow.WorkflowMetadataQuery`) with the workflow type and every registered query, signal and update. See [Stack trace and metadata queries](https://github.com/mikeacjones/temporal-sdk-zig/blob/main/README.md#stack-trace-and-metadata-queries).
Query, signal and update handlers take a `.description`, shown in the `__temporal_workflow_metadata` answer: `workflow.QueryHandlerOptions` with the new `Context.setQueryHandlerWithOptions`, `workflow.HandlerOptions.description`, and the same field in a struct workflow's `queries`, `signals` and `updates` entries, such as `.{ Status, .{ .description = "..." } }`.
