`client.Options.headers`, `client.ConnectionOptions.headers` and `Client.updateHeaders` accept gRPC binary headers: a name ending in `-bin` may carry any bytes, which gRPC sends base64-encoded, including a `-bin` header set with `TEMPORAL_GRPC_META_<NAME>` or a config profile's `grpc_meta` and loaded with `client.loadOptions`. Before, a `-bin` name was rejected with `error.InvalidOptions`. Any other header's value must still be visible ASCII, space or tab, and `error.InvalidOptions`, logged, names the header whose value isn't. Two headers whose names differ only in case are now rejected too, instead of one of them being sent at random; a name repeated exactly still sends its last value.
