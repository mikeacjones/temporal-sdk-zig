`Client.executeWorkflow` and `Client.executeWorkflowByName` start a workflow with `client.StartWorkflowOptions` (ID, task queue, timeouts, ID reuse and conflict policies, retry policy, cron schedule, memo, search attributes, priority, start delay, eager start) and return a `client.WorkflowRun` whose `get` follows continue-as-new to the result; `Client.getWorkflow` makes a handle to an existing run.
`Client.signalWorkflow`, `Client.queryWorkflow`, `Client.updateWorkflow`, `Client.signalWithStartWorkflow` and `Client.updateWithStartWorkflow` send typed messages declared with `workflow.SignalDef`, `workflow.QueryDef` and `workflow.UpdateDef`, or by name; update handles wait for a chosen stage.
`Client.describeWorkflow`, `Client.fetchHistory`, `Client.historyIterator`, `Client.listWorkflows`, `Client.countWorkflows`, `Client.cancelWorkflow` and `Client.terminateWorkflow` inspect and manage runs.
