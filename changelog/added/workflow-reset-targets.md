`ResetOptions.target` makes `Client.resetWorkflow` find the reset point itself: the run's first or last workflow task, or the first workflow task a given build ID completed; `workflow_task_finish_event_id` now defaults to 0 and is set only when no target is. See [Workflow reset and execution options](https://github.com/mikeacjones/temporal-sdk-zig/blob/main/README.md#workflow-reset-and-execution-options).
`ResetOptions.post_reset_operations` changes the new run's execution options as part of a reset, each entry a `WorkflowExecutionOptionsChanges` the server applies in order. See [Workflow reset and execution options](https://github.com/mikeacjones/temporal-sdk-zig/blob/main/README.md#workflow-reset-and-execution-options).
`client.resetPointEventId` finds the event ID of a history's first or last completed workflow task, or of the last one completed at or before a given time, to pass as `ResetOptions.workflow_task_finish_event_id`. See [Workflow reset and execution options](https://github.com/mikeacjones/temporal-sdk-zig/blob/main/README.md#workflow-reset-and-execution-options).
`Client.resetWorkflow` returns `error.NoResetPoint`, and resets nothing, when `ResetOptions.target` finds no reset point in the run. See [Workflow reset and execution options](https://github.com/mikeacjones/temporal-sdk-zig/blob/main/README.md#workflow-reset-and-execution-options).
`WorkflowExecutionOptionsChanges.priority` changes a running workflow's priority and fairness with `Client.updateWorkflowExecutionOptions` (server 1.30 or later), and `WorkflowExecutionOptions.priority` reads it back. See [Workflow reset and execution options](https://github.com/mikeacjones/temporal-sdk-zig/blob/main/README.md#workflow-reset-and-execution-options).
