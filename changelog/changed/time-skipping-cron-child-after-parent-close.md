The documentation of `testing.WorkflowEnvironment.getResult` and the README's time-skipping notes now state that on the time-skipping server a cron child, or any other pending timer, can fire once more between a run closing and its result being read, and that the time-skipping server doesn't apply a parent-close policy: a child of a closed run, cron or not, keeps running and runs again on every later time skip, so a test reads a child's run count right after its parent's result or terminates the child through `env.client`.
