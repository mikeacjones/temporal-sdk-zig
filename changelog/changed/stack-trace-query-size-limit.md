The worker's answer to the `__stack_trace` query is now limited to 256 KiB of text, so a workflow with thousands of live coroutines no longer gets an answer past the server's gRPC message limit: entries that don't fit are left out from the last started, and the answer's last line says how many, such as `1200 more coroutines not shown: the answer is limited to 262144 bytes`. The first line still counts every coroutine, and an answer that fits is unchanged.
